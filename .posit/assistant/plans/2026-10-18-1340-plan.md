# Plan: move the games-family ingest mapping into targets (dynamic branching)

## Problem

`raw_games`, `raw_game_team_stats`, and `raw_game_player_stats` are single
targets whose ingest functions loop over years × season-types × weeks inside
`R/ingest.R`. One failed call (CFBD 429/503 is common) aborts the whole target,
and the next run re-pulls every week from scratch — roughly 1,150 throttled
calls wasted per restart.

## Approach

Split the mapping into **dynamic branching** so each branch result is cached
independently in `_targets/objects/`. On re-run after a failure, `tar_make()`
only executes the branches that failed or hadn't run; completed weeks are never
re-ingested.

### 1. New chunk helpers in `R/ingest.R`

Keep the existing full-table `ingest_*()` functions untouched (they remain the
documented programmatic API); add small chunk functions the targets call:

- `ingest_games_chunk(year, season_type)` — one `/games` call; returns `NULL`
  for an unplayed season type (as today). Reuses the mutate/select logic
  currently inline in `ingest_games()` (extract it into the chunk helper and
  have `ingest_games()` not duplicate it — simplest: `ingest_games()` keeps its
  current body; only the chunk helper is new).
- `ingest_game_team_stats_chunk(year, week, season_type)` — one
  `/games/teams` call + `flatten_game_team_stats()`. Weeks are passed in
  directly, so `weeks_for_year()` is no longer needed by the chunk path.
- `ingest_game_player_stats_chunk(year, week, season_type)` — same for
  `/games/players` + `flatten_game_player_stats()`.

All three keep the existing `cfbd_game_get()` pacing/retry budget
(1 call/s, 10 tries / 600 s, decision 0028) unchanged.

### 2. `_targets.R` ingest stage changes

```r
# /games: branch per season (x season type) — 34 seasons x 2 types = 68 branches
tar_target(
  games_grid,
  tidyr::expand_grid(year = 2010:2026, season_type = c("regular", "postseason"))
),
tar_target(
  raw_games_chunk,
  if (refresh_enabled()) ingest_games_chunk(games_grid$year, games_grid$season_type),
  pattern = map(games_grid)
),
# combine branches into the same full tibble downstream code already expects
tar_target(raw_games, tar_combine(raw_games, raw_games_chunk, !!!list(bind_rows)))
```

- `raw_games` keeps its current name and shape, so `clean_games()`, the
  `games_file` parquet asset, the audit step, and the DuckDB bundle are
  untouched.
- The stats endpoints branch over a week grid derived **in-pipeline** from
  `raw_games` (replaces the `games = raw_games` argument to the ingest
  functions):

```r
tar_target(
  week_grid,
  raw_games |>
    dplyr::distinct(season, seasonType, week) |>
    dplyr::arrange(season, seasonType, week)
),
tar_target(
  raw_game_team_stats_chunk,
  if (refresh_enabled()) ingest_game_team_stats_chunk(
    week_grid$season, week_grid$week, week_grid$seasonType
  ),
  pattern = map(week_grid)
),
tar_target(raw_game_team_stats, tar_combine(raw_game_team_stats, raw_game_team_stats_chunk, !!!list(bind_rows))),
# same for raw_game_player_stats_chunk / raw_game_player_stats
```

  ~570 week branches per endpoint; each cached branch is a small tibble, fine
  under the current `format = "rds"`.

### 3. Resume semantics (what the user asked for)

- Within a failed `tar_make()`: each finished week/season branch is already
  written to `_targets/objects/`. The next `tar_make()` runs only the failed /
  remaining branches, then the combines — no re-pull of completed weeks.
- Across scheduled refreshes: `refresh.R` invalidates the ingest targets, so a
  true refresh re-runs branches — but each branch is now one cheap API call, so
  an interrupted refresh loses at most the in-flight call, not the sweep.

### 3b. Impact on existing completed targets (no work is thrown away)

- **In refresh/track mode today, the `raw_*` ingest targets only run in refresh
  mode** (they're `NULL` in track mode, and refresh.R invalidates them on every
  explicit refresh). So this restructuring does not "un-complete" any cached
  data that matters operationally: the next real refresh does a full pull
  either way, and on that first branched run there is no branch cache yet —
  it costs the same ~1,150 calls as today. The resumability benefit starts
  with every failure/restart *after* that first run.
- **Name/code changes invalidate:** `raw_games`, `raw_game_team_stats`,
  `raw_game_player_stats` change their command and gain new upstream targets
  (`games_grid`, `week_grid`, the `*_chunk` targets), so `tar_make()` will
  consider them out of date and re-run them on the next refresh — expected,
  since they're ingest targets that refresh.R invalidates anyway.
- **Downstream nodes stay valid if values are unchanged:** `clean_*` /
  `parquet_asset` targets and everything below them (contracts, audit, DuckDB)
  re-run only if the *value* of the combined tibbles differs from what's
  cached. Since the branch+combine path produces the same rows as the current
  loops (same endpoints, same flattening), downstream targets should be
  recognized as up to date after the next refresh — targets compares hashes,
  not code, for downstream invalidation.
- **Track mode / CI site build:** `raw_*` are NULL there, the new grid/branch
  targets also return NULL, and the cleaned parquet assets are tracked files —
  completely unaffected.

### 4. Guardrails / follow-ups

- Empty branch results (unplayed postseason, future seasons) bind cleanly via
  `dplyr::bind_rows`; no contract changes needed — the combined tables have the
  same grain as today, and `ok_games` / `ok_game_team_stats` /
  `ok_game_player_stats` keep checking them.
- `weeks_for_year()` and the `games =` parameter of the full-table
  `ingest_game_*_stats()` stay (public API), but the targets no longer use
  them; doc comments updated to note the pipeline path.
- `tar_combine` needs a named-combine function: use `dplyr::bind_rows` (already
  a pipeline package).
- Add tests (testthat) for the three chunk helpers with a mocked
  `cfbd_game_get` (fixture-based, like existing ingest tests if any — match
  existing test style).
- Record the change in `decisions/` (new numbered entry: branching the
  games-family ingest for resumability) and add a NEWS.md line before merge.
